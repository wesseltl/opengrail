# Contributing to OpenGrail

The owner permits public OpenGrail source, superseding the earlier private-only preference. The owner-created project repository [wesseltl/opengrail](https://github.com/wesseltl/opengrail), ID 1414301089, was verified PUBLIC on 11 October 2026. The application foundation is published on `source/opengrail-foundation` at [e727f28](https://github.com/wesseltl/opengrail/tree/e727f28ad9772abd8f8c165dd016c02c22715fbc); all 575 file contents and modes were verified. Default `main` contains a README directory. Starter issues #1–#3 are published, while hosted CI and public API availability remain unverified. The connected integration cannot administer visibility/protection. Public source grants no merge, deployment, production or private-data access. Public research onboarding uses `/agent-guide` and requires no source access. The public CI collector and optional version-two private CI collector remain separate, reviewed paths; private read credentials and evidence never belong in public discussions.

Useful contributions make collaboration safer or make evidence easier to reproduce. Documentation, accessible interaction design, security reviews, test cases and carefully scoped implementations are welcome from humans and agents.

Start with [the agent contributor kit and actual starter issues](docs/agent-contributor-start.md#three-bounded-first-tasks), then read [the task index](docs/tasks/README.md). Check whether an issue or pull request already covers the work, explain the problem and agree on a bounded change. Published issues do not register platform tasks, award claims or establish accepted contributions.

The source-prepared [contribution desk](docs/contribution-desk.md) adds public coordination without repository access. Claim only an exact current task. The [prepared public handoff](docs/public-contribution-handoff.md) binds local task/claim snapshots, a declared public issue mapping and retained checker evidence; the existing private handoff remains separate for approved private work. Only the artifact's byte digest enters platform submission. A coordination disposition does not approve merging, establish a completed task or award reputation. Its additive migration, policy and separate maintainer role need rollout approval.

Fork the verified repository and create a focused branch from `source/opengrail-foundation`. Agree scope and hosted workflow authorization with a maintainer before opening a pull request; `main` is currently a README directory. Include the task reference, observable before/after behavior, relevant failure cases and the results of `npm test`, `npm run typecheck`, `npm run build` and `git diff --check`. If a command is unavailable or fails, explain that accurately. Do not remove checks merely to obtain a passing result. Preparing a contribution does not require an OpenGrail account; the `/contribute` guide is prepared source pending approved rollout.

Agent-authored contributions need the same review as human contributions. Identify the contributing agent and human sponsor where applicable, describe the parts produced by automation and confirm that the sponsor has permission to submit the material. Do not attribute claims, tests or independent review to a person who did not perform them. Submission does not grant a license beyond the applicable contribution terms; the project must publish its license before describing license-dependent reuse rights.

Use synthetic examples and properly licensed public data. Do not include personal account details, raw agent credentials, private Capital Desk code or data, exchange credentials, API keys or unpublished financial material. Report sensitive vulnerabilities through [the security process](SECURITY.md), not a public issue.

A maintainer decides whether to accept and merge the change. Merging, deployment, permission changes, paid infrastructure and access to production data require explicit maintainer approval. Fork pull requests must be tested without secrets or privileged CI; contributors run external agents on their own chosen infrastructure. There is no promise of free hosted agent compute, compensation or trading returns.

The contribution-check workflow, local runner and read-only current-PR evidence path are source preparation, with coordinated local checks passed. The public application repository is verified; actual hosted workflow execution is unverified. A locally generated report is not an independent attestation. `CI_VERIFIED` describes complete successful configured checks for an exact current source, not research qualification, security certification or approval to merge. See the workflow for commands and maintainer-reviewed policy requirements; do not invent a policy, PR or hosted run.

For a reviewed exact two-parent test merge, run `node scripts/check-contribution.mjs BASE_SHA HEAD_SHA TESTED_MERGE_SHA NEW_REPORT.json` from the checkout. Replace the SHA placeholders with full lowercase 40-character commit identities. Replace `NEW_REPORT.json` with a new absolute report path outside the checkout; both conditions are required. The checker emits bounded `LOCAL_CHECK_REPORT` evidence with `PASSED`, `FAILED` or `INTERRUPTED`, qualification `NONE` and exact source/check identities. Include adverse results rather than replacing them with a passing rerun; inspect retained command output for sensitive material before sharing. The fixed test ceiling is 75 minutes, other checks retain 20-minute ceilings, and metadata/check execution shares an 80-minute monotonic budget. See [the local check limits](docs/contribution-ci.md#retained-local-report) for timeout dispositions, lower-only overrides and the separate hosted limit; these budgets are not an execution sandbox.

The [contribution workflow](docs/contribution-workflow.md) explains review evidence and [AGENTS.md](AGENTS.md) defines the limits for automated contributors.

Start with the [agent contributor kit](docs/agent-contributor-start.md): three bounded source tasks, operator sponsorship and evidence expectations. Hosted agent API participation remains a separate rollout.

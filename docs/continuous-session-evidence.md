# Share a continuous Demo checkpoint

The existing Session kernel keeps open inventory at the end of a supplied stream. Its evidence must preserve that behavior. The continuous experiment branch is distinct from batch Demo replay and its tail liquidation.

## Prepare locally

Keep the full original journal. In Session, prepare a public checkpoint and export its review file. This captures a specific immutable event prefix; it does not pause, close or publish the session. Import that file in Experiments to review the registration and its later outcome.

A sponsor-local agent can use the same fixed source without an AI API or network connection:

```sh
node scripts/session-evidence.mjs prepare JOURNAL.json NEW_REVIEW.json
node scripts/session-evidence.mjs verify NEW_REVIEW.json
```

The command accepts bounded regular JSON files, imports only fixed local first-party modules, checks the pinned Session implementation and refuses overwriting any existing output. Preparation reconstructs the original journal. Verification checks a supplied artifact against that same kernel. A local preparation refusal records a small rejection receipt when its new output can be written; the original journal remains intact. The tool makes no public submission and accepts no credential or remote endpoint.

For a current-source invented example, run `node scripts/example-sessions.mjs`, then prepare `examples/sessions/20261011/signal-open.json`. The dated directory also retains the pending emergency and adverse-exit checkpoints. These remain `SYNTHETIC_PLAYBACK`, with no authentic market feed, independent qualification or profitability evidence.

The older `examples/sessions/*.json` files remain archived with their original source fingerprints and exact bytes. Current-source guards reject their earlier implementation identity; that refusal does not authorize rewriting the journal, repairing its fingerprints or relabeling it as a current result. Preserve historical checkpoints with their matching source. Generating the new dated examples creates new synthetic evidence rather than reproducing an archived journal under a different implementation.

## Review and publish explicitly

The version-two `CONTINUOUS_DEMO` manifest freezes the configuration, start, fixed implementation and method identity, retrospective hypothesis/falsification, every normalized event, original receipt time and intermediate commitment. It retains the original journal digest and terminal state/receipt identities. The tape starts at creation and ends at the declared checkpoint; rejected normalized events and clock regressions stay in their original order.

Review the exact visible public strategy, all input data and search/conflict disclosures. Local permission to use supplied market data is separate from permission to redistribute it publicly. Each publication consent starts unchecked; confirm rights to the full tape and artifact before explicitly registering. Registration proves registry receipt time, not preregistration, original system intake or independent data authenticity.

After registration, append the prepared artifact through the existing outcome form. Its input must exactly match the manifest. Reproductions and conflicts reference outcomes under that same exact input. If more events arrive, prepare a new checkpoint and register a new manifest. Different tapes cannot become reproductions just because their Session configuration matches.

For an unknown acknowledgment, retain and retry the identical request, record ID, command and authenticated principal. Do not create another request to guess whether the first was accepted. Fresh source/parent visibility applies to reads, preparation and retries; hidden material is suppressed rather than republished from a held draft.

## Interpret the evidence

The outcome keeps account mark/source times, open positions, pending admission or emergency exit, status/failure, data gaps, capacity halts, counts and uncapped losses. There is no forced liquidation, batch benchmark or claim that the latest mark is a currently executable price.

Validation performs **same-kernel reconstruction**, comparing every intermediate state commitment, the original full-journal identity and terminal projection. A structurally self-consistent fabricated artifact may be retained by the server as an author claim; local reconstruction can reject its computation. The server does not run evaluations or submitted code.

Everything remains `AUTHOR_REPORTED`, qualification `NONE`, independence `NOT_ESTABLISHED` and source authentication `UNKNOWN`. The complete retained tape cannot prove that upstream events, malformed requests, alternate sessions or earlier research attempts were never omitted. Matching local computation does not prove achievable returns, unseen data or independent performance.

## Keep oversized or incomplete evidence honest

Existing limits remain: 192 KiB exact input, 256 KiB manifest, 512 KiB artifact, 576 KiB outcome and 768 KiB request. Both experiment methods share existing sponsor/day, global and per-manifest quotas. No automatic eviction or reset is introduced.

Compaction removes duplicated derived history, not events. Some complete sessions still exceed the public input budget. Preserve those full journals locally and retain the preparation rejection; do not slice the tape, repair clocks or advertise a partial prefix as the same checkpoint. Without a fitting exact input there is no manifest to which an unavailable artifact can be attached. When the exact input fits but its result does not, an explicit `ARTIFACT_UNAVAILABLE` outcome may retain that disposition without metrics or a success claim.

This source extension is prepared for maintainer review. It introduces no hosted receiver, provider permission, public credential scope, risk change, private account connection or Live order authority.

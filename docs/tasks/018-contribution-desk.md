## Required behavior

- Human maintainers are explicitly configured through a new separate permission, empty by default. Existing participation, sponsorship, moderation and experiment-review permissions do not imply task curation/review. Agents can only claim, release and submit attributable public coordination records.
- Tasks have immutable public descriptions, acceptance/rejection criteria, canonical hashes and explicit publication policy consent. Changing a task means creating a new immutable task. Closure/hiding are retained terminal lifecycle events with exact previous-state checks. Hidden task content and dependent authored claim/event payloads stay suppressed.
- A task admits one current 72-hour lease. Claims bind the exact task digest and current task sequence. Expired, released, rejected and accepted attempts remain retained. Submission and changes-requested states retain the original deadline; no extension or renewal is invented. Closed/hidden tasks block new dependent submissions; authorized release can still reconcile and terminate existing work.
- Every command binds a server-derived participant, original request ID, exact references and expected event sequence where relevant. Concurrent claims have one winner. Current agent registry and expiry/revocation checks fence admission, mutation and receipt disclosure. A human sponsor may release their own agent’s claim without acquiring its authorship.
- Submit only a SHA-256 private handoff digest; never repository, issue, PR, source, token, private evidence or uploaded code. Maintainer ACCEPTED/CHANGES_REQUESTED/REJECTED decisions record narrow coordination review and fixed public reasons, preserving original attempts. They do not prove merged PRs, completed tasks, safe code, independent research, reputation or profitability.
- Atomically enforce finite new contribution-specific daily and retained bounds without altering existing network/research/strategy/experiment limits. Retained capacity has no automatic reset. Exact accepted retries consume no additional quota; no cleanup deletes failed work.
- Anonymous task/claim reads and authenticated human/agent commands use strict bounded contracts. Reject unknown/duplicate query keys, unsupported methods, duplicate JSON keys, excess bytes/depth, credential-shaped text, forged authorship/privileges, foreign references and changed retry bodies. Public API responses must correlate exact identity/digest/current lifecycle and remain bounded.
- The UI retains the exact pending command, serialized body, request ID and original human principal after uncertain replies. Lock dependent actions until an identical retry reconciles. Identity changes, stale pages and hidden records clear dependent authored content; no browser durable secret/state store or automatic publication.
- A private file-only handoff prepares/verifies bounded strict local data against exact public task/claim, PRIVATE policy and CI snapshot. Include unsuccessful, stale or unavailable evidence without promoting it to verified execution. Preserve operator isolation declarations and offline authenticity limits. Output is exclusive mode-0600 outside trusted/working checkouts; terminal summaries expose no private GitHub details. No token read, provider call, contributed-code execution or external mutation.

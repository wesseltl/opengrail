# 024: Shared contribution task discussions

Source proposal; no production migration, policy/role grant, GitHub setup or deployment is authorized. Read AGENTS.md, the existing contribution/network/research contracts and required checks first. Preserve all old table/schema/migration bytes, risk limits, permissions and writers.

## Outcome

Multiple humans and sponsored external agents can ask questions, propose public documentation/test specifications, provide counterexamples and peer comments on an exact contribution task. Participation requires no work claim and grants no private source, task acceptance, CI trust, merge, execution, reputation or financial authority. The owner's latest instruction permits public OpenGrail source: public documentation, repository links and snippets may be shared as inert bounded plaintext. Credentials, private code/data, confidential handoffs and uploaded executable material do not belong in public messages. Authored material remains unverified.

## Protocol

Add `app/task-discussion-model.ts`, `app/task-discussion-store.ts`, `app/task-discussion-http.ts`, actual routes under `/api/contributions/discussion`, `/agent`, `/me`, `/reports`, and an integrated human task discussion surface/anonymous agent guide. Use the existing fixed PUBLIC_RESEARCH_SUBMIT scope and separately configured human contribution maintainer (empty by default); do not change either existing interpretation/configuration. Proposed extensions need review before rollout.

Model exports: `taskDiscussionLimits`, `taskDiscussionPolicy`, `TaskDiscussionCommand`, `TaskDiscussionActor` (existing ContributionActor), strict record/event/report/item/list/get/write/report-list schemas; bounded command/record/event/report builders, canonical record builders and `validateTaskDiscussionItem` / `validateTaskDiscussionWrite(raw,command,publicAuthor)`.

- `publish`: action, id, requestId, task{id,digest}, expectedTaskSequence, claim:null|{id,digest}, replyTo:null|{id,digest}, kind QUESTION|PROPOSAL|COUNTEREXAMPLE|PEER_REVIEW, body, policyAccepted. Exact visible OPEN task required at read and atomic insert; optional claim must belong to that task, reply must be a currently visible same-task message. No claim ownership prerequisite, no executable uploads/attachments, no authored trust/privilege fields. Public snippets are rendered as text and never executed.
- `withdraw` / `hide`: action, requestId, task, message{id,digest}, expectedSequence, reason, policyAccepted. Withdraw author-only; hide explicit human contribution maintainer-only. Terminal hide plus one reserved author-withdrawal slot; never restore. Task-hidden records remain retained with content suppressed on every read and identical retry. Withdrawal can reconcile/terminate when task closed/hidden.
- `report`: action, requestId, task, message, category, details, policyAccepted. Bounded private report; only explicitly authorized human contribution maintainers can read the separate queue. Public receipts never expose details or other reports.

Canonical message record: version1,id,requestId,createdAt,author,task,claim,replyTo,kind,body,policyAccepted,executionEnabled:false. Event binds exact task/message, actor, requestId, createdAt, action, expectedSequence/sequence, state/reason and policy. Item retains stable id/digest/requestId/author/createdAt/task/taskState/sequence/state, record|null and events; suppress authored payloads for task hide/message hide/withdraw without deleting history. Write response: version1, action,requestId, acknowledgement{actor,commandDigest,digest,createdAt,sequence}, task, message|null, report:null|bounded private report acknowledgement. Publish sequence0; event sequence advances; report sequence0. UI/API validator binds exact original body, author, target, clocks and current projection; changed original request bodies conflict.

Limits: request8192B, record6144B, event4096B, report2048B, response262144B, depth12/nodes4096, page16, body4000chars, 2000 retained messages,64 per task,20 messages/sponsor UTC-day,2 events/message with withdrawal reserve,2000 private reports,10 reports/sponsor UTC-day. New actions share an author/request namespace within the three new tables; do not alter legacy namespaces or quota pools. Report payloads and events have strict typed fixed reasons/categories. Reject credentials raw/encoded/malformed prefixes, hooks/prototypes/cycles/nonfinite/duplicate JSON, unsupported methods/query keys, forged authorship and foreign references.

Repository methods: `list(taskId,taskDigest,cursor|null,at)`, `get(id,at)`, `write(actor,command,at)`, `reports(cursor|null,at)`; rows are bounded and canonical/digest checked before projection. Mutations atomically fence source bytes/lifecycle, optional claim/reply bytes, current agent credential (including commit clock), exact expected state, namespace, sponsor daily/global/per-task retained capacities. Unknown acknowledgements reconcile the original row; no double charge, omission, eviction, payload repair or second write. Final source/current credential checks precede receipt. Public page uses complete bounded stable pagination with exact cursor correlation and final visibility fence.

HTTP: anonymous GET `/api/contributions/discussion?task=UUID&digest=SHA256[&cursor=UUID]` or `?id=UUID`; human POST same endpoint requires same-origin JSON, X-Task-Discussion-Intent:submit and X-Task-Discussion-Author matching current human pseudonym. Agent POST `/agent` requires HTTPS/Bearer, no URL credentials, permits publish/withdraw/report only. `/me` mirrors contribution identity. `/reports` human-maintainer-only GET with bounded canonical private cursor. No server evaluator, provider, paid inference or source execution.

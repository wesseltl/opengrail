# 009 — Frozen chronological experiment plans

Status: implementation integrated; 615/615 coordinated tests, typecheck and build passed. Native source-save verification follows separately; no public deployment. This extends the existing exact experiment workflow; it does not complete independent qualification or establish unseen data.

## Problem and intended behavior

A full-input replay can hide a strategy's deterioration on later data. Prepare a frozen, reproducible chronological training/test protocol, register each exact partition separately and retain both successful and adverse runs. A supplied public dataset is already exposed; splitting it does not make the test data untouched.

## Scope

- Capture one exact visible original manifest and strategy. Freeze the partition boundary, excluded gap, source identities, costs, capital, disclosures and stable child registration identifiers before local computation.
- Use contiguous nonoverlapping partitions, independent initial capital and each partition's own warmup. Carry no positions, cash, indicator history or consumed signals across the boundary.
- Include a signal only when both its observation and availability belong to that partition. Retain exclusion reasons, original timestamps and emergency-stop semantics; never move signals across a boundary to manufacture a fill.
- Prepare two exact existing-schema child registration drafts. Each publication is explicit, quota-counted and separately consented. Correlate real child records to their frozen command before invoking the existing exact runner.
- Retain bounded frozen plans and admitted failures, losses, evaluator disagreements, no-trade outcomes, cancellations and incomplete pairs. Changing a boundary or assumption creates another plan; do not overwrite adverse evidence.
- Support human UI and sponsor-local agent workflows without a particular model, paid inference, hosted computation or automatic public submission.
- Keep results AUTHOR_REPORTED, qualification NONE and independence/unseen data NOT_ESTABLISHED. Preserve prior search, selection, access and reuse disclosures.

## Acceptance evidence

1. Training gains followed by a test loss remain visible together. Future test prices cannot affect the training artifact.
2. Boundary/gap signals and delayed availability cannot leak across partitions. Narrow valid partitions can honestly produce NO_TRADES.
3. Separate child artifacts match their exact registered inputs; original-full-manifest binding and changed child receipts fail.
4. Partial registration and unknown acknowledgments preserve each exact command and principal for identical retries. Preparing drafts resets sharing consent and sends no HTTP write.
5. Current-source checks, withdrawal, cancellation, signout and unmount fence stale work and clear dependent payloads. Independent child publications do not gain server-enforced original-parent suppression from a local plan.
6. Local plan files use bounded strict data, fixed first-party code and create-new durable exports. No submitted code, URLs, provider, exchange account or raw token is executed or contacted.
7. Existing required checks and meaningful core/CLI/component cases pass against actual implementation. Real-browser, hosted, unseen-data and independent-review acceptance remain separate.

## Purpose

Connect the existing continuous Demo journal to public review without converting it into a batch replay, discarding rejected events or pretending open inventory was liquidated.

## Acceptance

- Add an explicit version-two `CONTINUOUS_DEMO` branch alongside the unchanged version-one batch contract. Keep the existing database, sponsorship, credentials, moderation, pooled quotas and byte limits.
- A retrospective manifest freezes the exact configuration, start, fixed implementation identity and complete normalized event prefix with its original receipt times and intermediate commitments. A later checkpoint requires a new manifest. Registration cannot prove preregistration or authentic event delivery.
- A bounded artifact binds that exact input to the declared terminal account, open inventory, pending controls, failures, data gaps and original journal identity. Do not invent a batch baseline, tail liquidation or independent evaluator.
- The server checks bounded structure, hashes and exact source/manifest correlation. Only the local fixed Session implementation reconstructs all events and checks every intermediate commitment and the terminal projection.
- Session preparation and Experiments review require a visible exact public strategy, fresh checks and separate public-sharing consent. Preparation does not publish, pause or stop the session. Uncertain publication retains the original identity and request body.
- Preserve the complete local journal if its compact input exceeds 192 KiB. Refuse publication rather than truncating. An unavailable outcome is appropriate only when its exact parent manifest can be retained.
- The existing Validation reader dispatches this method to same-kernel reconstruction and refuses batch comparison or chronological-plan controls for it.
- Actual fixtures cover open positions, emergency exits awaiting a quote, adverse exits, rejected receipt-clock regressions, insolvent losses, self-hashed false evidence, current-source suppression and additive batch compatibility.

## Boundaries

Evidence remains `AUTHOR_REPORTED`, qualification `NONE`. Reconstruction does not authenticate market sources, prove a complete upstream delivery history, establish unseen data or qualify performance. No Session kernel, fixed pins, provider, receiver authority, risk limit, financial account or production configuration changes are authorized by this task.

# Locked search to forward Demo

Implementation acceptance criteria, not proof of deployed behavior or genuine market performance. The goal remains the complete public collaboration platform in PRODUCT_GOAL.md.

## Problem and resulting workflow

The local search locks a TRAIN-selected strategy and retains its TEST history, but Session setup currently loses that provenance. The optional Kraken producer retains response hashes without raw observations or the exact normalization clocks. Connect these paths: export the complete locked search, import it into Session without retyping or retuning, freeze a prospective plan with the exact existing receiver configuration, and retain inspectable raw observations before the unchanged producer delivers normalized events.

## Fixed boundaries

Keep the existing search protocol, Demo evaluator/reference, Session model/engine/journal/fingerprints, Kraken producer/core, receiver and their limits byte-identical. No dependency, database, role, quota, hosting, private Capital Desk, Live, paid inference or external outreach changes. The new collector uses the old fixed public GET and loopback producer-only receiver interface; no strategy code, caller-selected URL or shell command is executed. Owner credentials remain separate. Real provider use requires the existing explicit operator acknowledgements; synthetic acceptance supplies neither a license nor authorization for a real run.

## Protocol contract

Add `app/forward-demo-model.ts` with a separate bounded `LOCKED_SEARCH_HANDOFF` and `LOCAL_FORWARD_DEMO_PLAN`; do not extend the strict Session configuration. Export `createLockedSearchHandoff(ledger)`, `verifyLockedSearchHandoff(raw)`, `createForwardDemoPlan({handoff, config, preparedAt, startsAt, endsAt, pollMs, cycles})`, `verifyForwardDemoPlan(raw)` and their types/limits. Preserve the complete verified ledger and every failed/interrupted/losing attempt. Require a locked SELECTED outcome and no pending attempt. Freeze the exact winning public strategy record/digest, capital, costs/risk, hypothesis/falsification, Session SYSTEM_RECEIPT/PUBLIC_STRATEGY/USER_SUPPLIED config, canonical configuration digest and current implementation identities. A future nominal interval must start after preparation and all retained selection/attempt clocks; no source timestamp is advanced. These are author-declared clocks, not independent precommit evidence. Declared interval completion and finite producer-budget completion remain distinct.

The selected strategy cannot change within this context. Kraken's existing adapter supplies closed bars and sampled last trades, not signals; a SIGNAL strategy is unsupported by this particular collector and must never receive invented signals. Flags remain AUTHOR_REPORTED/NONE, independence and provider authenticity unestablished, orders/live disabled.

Add fixed first-party `scripts/forward-demo-core.mjs` exports `loadForwardDemoModules()`, `cleanupForwardDemoModules()`, and `readForwardDemoPlan(path)`, usable by the new CLI and recorded collector. Use the repository's guarded fixed compilation pattern and private bounded file rules. Add a prepare/verify CLI; preparation supplies the actual process clock, while verification does not upgrade historical declarations to a current admission.

## User journey

Search offers `Prepare forward Demo` only for an eligible locked result. Export the complete handoff after fresh exact public-source checks. Session offers `Import locked search`, verifies the whole handoff, checks the current public source and fills the exact winner/capital. Show retained TRAIN dispositions and adverse TEST outcomes. Data rights are acknowledged anew. Export the ordinary canonical receiver config and a separate plan that binds it to the retained search. Keep export identity stable on identical retries. Changing setup explicitly abandons the locked context; hidden/withdrawn source, account/navigation changes or uncertain work suppress dependent exports. Do not launch a local collector automatically or persist credentials/search evidence in browser storage.

## Raw observation capture

Add a separate recorded adapter composing the unchanged `runProducer` dependency hooks. Persist a request attempt before each fixed GET; preserve bounded exact response-body bytes (not claimed wire/TLS bytes), status, outcome, SHA256 and exact normalization clock before receiver delivery. Bodies live in an exclusive private archive with ordinal-owned filenames; no input selects filesystem paths. Bind successful raw observations to the durable producer outbox before delivery. Preserve failed, partial, malformed, oversized, interrupted, uncertain and unused observations. Retain the existing 120-poll/240-GET/event/delivery budgets; do not reset them or prune evidence. Resume only matching original histories; no retrospective raw-body grafting onto legacy feeds.

Cross-file failures preserve all possible committed files and halt intake with uncertainty. Keep original event UUIDs and reconcile retained receiver acknowledgements. Fresh admission requires the exact generated config and original receiver instance/start. A separate verifier checks raw bytes to existing normalization, outbox event content/digests and the complete reconstructed receiver journal. Receipt lookup digests may refer to a later journal prefix than the original receipt sequence. Every receiver market event must be mapped; owner controls remain separately retained. Warmup is not forward trading. Incomplete horizons, missing signals, feed gaps, open inventory and losses remain visible; no fabricated closing quote or tail liquidation.

## Acceptance

Prove the actual integrated local path using isolated synthetic inputs: locked TRAIN winner with retained adverse TEST history → exact forward receiver config → actual receiver and unchanged producer composition → raw-response capture → normalization/outbox/full-journal reconstruction. A real local-process prospective test must not backdate its receiver journal. Separately injected synthetic-clock fixtures can exercise a loss and owner emergency. Cover altered winner/config/capital, malformed/credential-bearing material, past windows, source suppression, retry stability, raw-body tampering, HTTP/body failure, storage races/capacity, clock faults, unmatched market inputs, lost acknowledgements and partial horizons.

Retain exact check outputs and failed attempts. Full selection with bounded concurrency, typecheck and official Sites build must pass on frozen final inputs. Save an archive-backed Sites version without deployment; publishing public source must preserve exact reviewed content/modes and its expected branch head. Local evidence is not external custody, genuine prospective performance, independent reproduction, positive qualification, CI or rollout approval.

## Required product behavior

Implement assistance coordination, not a saved prompt masquerading as a strategy. A signed-in human publishes a typed natural-language request referring to one exact currently visible public strategy. A genuinely registered external agent publishes an actual strategy FORK of that base through the existing strategy API, then submits a typed response linking the exact request to its own exact proposal. The human sees the requested intent, constraints, rejection criteria, agent rationale/questions and field-by-field definition changes. Separate explicit adoption consent publishes an ordinary HUMAN FORK of that agent proposal through the existing strategy writer. Viewing, selecting or receiving a proposal never publishes or executes anything.

Reasoning runs on the external agent's chosen infrastructure. No built-in model, API credits, arbitrary code execution, guaranteed response or autonomous adoption is added. Requests are public only after explicit publication consent. They belong in /assistance rather than polluting the Strategy Hub with unchanged request definitions. All proposed strategies retain UNTESTED, Demo, leverage 1 and disabled orders/Live.

## Strict canonical contract

New assistance model exports `assistanceLimits`, `AssistanceError`, `assistanceCommandSchema`, `boundedAssistanceCommand`, `assistanceRecordSchema`, `boundedAssistanceRecord`, `assistancePublicItemSchema`, `assistanceListSchema`, `assistanceGetSchema`, `assistanceWriteSchema`, `assistanceReportsSchema`, and types `AssistanceCommand`, `AssistanceRecord`, `AssistancePublicItem`. Reuse canonical strategy author/reference/digest helpers, original strategy schemas and StrategyActor principals without extending scope or role strings.

All commands are strict, canonical, duplicate-key-free JSON; exact lowercase RFC UUIDs, exact 64-lowercase-hex digests, canonical ISO clocks, trimmed finite safe text. Reject credential material, including encoded public-agent/local-producer/owner prefixes, unknown fields and caller-supplied authority. Policy is literal `public-assistance-v1`. Command variants:

- `request`: action, requestId (operation), id (artifact), base:{id,digest}, intent (1–2000), constraints (1–1000), falsification (1–1000), policyAccepted. HUMAN only.
- `respond`: action, requestId (operation), id (artifact), request:{id,digest}, proposal:{id,digest}, rationale (1–1500), questions (0–1000), policyAccepted. AGENT only. Proposal must be an actual currently visible AGENT-authored FORK of the request's exact base, authored by this authenticated agent/sponsor. Bind each proposal to one response. The proposal must be created no earlier than the request, and the response no earlier than either; prior unrelated forks cannot be represented as a fresh answer.
- `withdraw`: action, requestId, id, digest, reason (safe author/sponsor reason), policyAccepted. Author or human sponsor only, terminal.
- `moderate`: action, requestId, id, digest, state HIDDEN|VISIBLE, reason (existing safe moderation reason enumeration), policyAccepted. Explicit existing research moderator only.
- `report`: action, requestId, id, digest, reason (existing public report reason enumeration), details (1–1500), policyAccepted. Private details, bounded maintainer queue; no public leakage.

Canonical request record order: version:1, kind:REQUEST, id, requestId, createdAt, author (full existing author), base, intent, constraints, falsification, policyAccepted, executionEnabled:false. Response order: version, kind:RESPONSE, id, requestId, createdAt, author, request, proposal, rationale, questions, policyAccepted, executionEnabled:false. Model validates kind/actor restrictions and public metadata/content correlation.

Public item: id, kind, digest, requestId, createdAt, author (reference), state VISIBLE|HIDDEN|WITHDRAWN, reason nullable, availability AVAILABLE|SUPPRESSED|DEPENDENCY_UNAVAILABLE, record nullable, moderation array. Own lifecycle stays distinct from current dependency suppression. AVAILABLE requires own VISIBLE and complete canonical content; SUPPRESSED requires non-visible own state and null content; DEPENDENCY_UNAVAILABLE requires own VISIBLE and null content. A currently hidden/withdrawn/missing base, request or proposal suppresses dependent content and blocks fresh preparation; current reads never restore cached content. Corrupt retained references fail closed, preserving rows.

Read wrappers: `{version:1,items,nextCursor,request:{id,digest}|null,executionEnabled:false}` and `{version:1,item,executionEnabled:false}`. Write wrapper: `{version:1,action,requestId,item,report,executionEnabled:false}`; report-only receipts have item:null and a private-details-free report, other actions have item and report:null. Immutable identities, exact commands/principals and full canonical available content must correlate on every write receipt; original redacted retries confirm identity without restoring content.

## Persistence and authority

New `AssistanceRepository(db)` implements `list(cursor=null, request=null)`, `get(id)`, `write(actor,command,at)`, `reports(actor,at,cursor=null)`. Default feed lists REQUEST artifacts; a request-filtered feed lists RESPONSE artifacts. A sole RESPONSE cursor derives its exact request from the validated retained anchor; list wrappers include that exact parent reference, while REQUEST feeds return request:null. Suppressed anchors never change feed scope. Enforce fixed bounds: page 12, request 16384 bytes, record 12288 bytes, 10 publications and 10 reports per sponsor UTC day, 1000 retained publications and reports, 16 lifecycle events per artifact, at most 32 responses per request. Retained suppressed/withdrawn records consume capacity; retries are free and never reset it. New local constants are not deployed quota configuration or billing caps.

Use additive assistance-publications, assistance-moderation and assistance-reports tables/schema/migration, no seeds or changes to prior migration bytes. Canonical payload hashes, command hashes, identities, parent/proposal references and lifecycle events are verified on reads/retries. Derive authors from the actual human identity or exact active registered-agent payload. Retain conditional SQL fences against revocation/expiry, reference digest/visibility drift, same-principal request-ID collision, response association collision, concurrent quota/final-slot admission and current lifecycle. Validate references via the actual StrategyRepository, then recheck exact immutable rows and latest moderation state atomically on insertion. Recheck dependencies for current read projection; do not follow caller URLs, fetch source links or execute code. No existing persistence writer, evaluator, strategy schema, identity scope/role, grants, dependencies or hosting configuration changes. The existing human strategy HTTP handler may add only an optional frozen-author header check before publication; callers omitting that header keep their existing behavior.

`/assistance` is a real client workspace with anonymous bounded request browsing, actual request publishing, response discovery and review. Exact query links support either base+digest for a request or request+digest for review; refuse unknown/duplicate/conflicting selections. Link assistance from current Strategy Evidence and shared navigation. Keep pending command, exact serialized body, original request ID, reference snapshots and human identity frozen in memory; uncertain response locks further publication and exposes identical reconciliation. Adoption sends existing public-strategy-v1 publish with relation FORK(proposal.id,digest), a new human-reviewed name and unchanged proposed definition, with optional `X-Strategy-Author` required by this workspace to fence its frozen human identity at the handler; request→response→proposal remains explicitly visible without fabricating automatic fulfillment.

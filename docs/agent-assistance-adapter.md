The example creates no proposal, operation ID, model invocation or automatic answer.

2. Call the example with the reviewed command and configured identity. 3. The controlling application reviews the exact prepared path/body and separately accepts public sharing. Only public read-only `boundary.tools` may enter model context. Keep the credential, controller, approval function, raw client and returned session outside it.
4. After consent, the example re-identifies and rereads the chain. Changed identity or projection stops before dispatch. These are current bounded snapshots, not an atomic lock across records; the server fences the mutation.
5. Inspect the receipt. CONFIRMED establishes attributable original acceptance with qualification NONE. Suppressed acceptance restores no content and starts no next stage. UNCERTAIN retains the original body, IDs and principal in the returned session. An unexpected dispatch exception returns a retained controller session for inspection, without claiming that a write succeeded or failed. Retain the original returned session after uncertainty and close it deliberately when finished; leaving the process can lose it. No recovery secret or durable credential persistence is invented.

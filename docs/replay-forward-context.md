# Continue a replay in forward Demo

For an ordinary public strategy, a confirmed Demo replay offers **Export forward context**. The file retains the selected original replay and every trial still available in that Demo page, including rejected, interrupted, losing and no-trade attempts. Then choose **Set up forward Demo**, and use **Import replay context** on the Session page. The link alone still carries only the exact public strategy ID and digest.

Import checks the full file and freshly confirms every retained public source with a held input, deduplicated by exact ID and digest. Metadata-only cleared/rejected source references do not cause a payload fetch. The selected strategy, costs, risk and initial virtual capital remain fixed; original hypothesis and falsification remain unchanged in the imported context. Describe the new input source and confirm its data permission separately. No Session, synthetic events, receiver, provider, publication or order starts on import.

Click **Start Demo session** only after reviewing the setup. This path uses system receipt, and the declared Session start must be strictly later than every retained trial attempt, bar and signal clock. Future-dated history can be inspected but cannot establish an earlier forward run. These are consistency checks on supplied chronology, not independent precommit or genuine provider timing. Deliver normalized events through the existing explicit event intake. Source timestamps remain author claims; prices and fills are never invented to complete the report.

**Export journey report** retains the unchanged replay context and the complete existing continuous-evidence bundle for the actual associated Session attempt. Exact strategy, capital and the attempt's retained context digest must agree. The original replay hypothesis stays in the context; editable forward-review hypothesis and falsification belong to the separate forward evidence. Existing checkpoint and review-bundle exports remain available. The combined journey wrapper is local and is not a new public-registry upload format.

Changing strategy/capital requires **Abandon replay association**. An existing Session and exposure remain visible and controllable; abandoning the association does not pause, stop or close it. Earlier attempts retain their context digest and cannot be relabeled with another replay. Combined reports from an abandoned association become unavailable in that page, with a safe disposition retained. Save files before leaving: context and history are page-memory only. Sign-out, navigation and source suppression clear dependent held payloads; exported files cannot be recalled. Cancellation and stale callbacks cannot attach a late import or export.

The context limit is 16 MiB, at most 32 page trials, and the combined report limit is 18 MiB. Existing full continuous-evidence input limits also apply. Oversized histories/checkpoints are refused in full; nothing is silently trimmed. Retaining all available page trials does not prove that other trials were never run. Both wrappers remain AUTHOR_REPORTED, qualification NONE and independence NOT_ESTABLISHED. Digests establish supplied byte identity, not correctness, independent reproduction, authentic data, profitability or a complete search history. Trusted first-party local verification is exposed by `verifyReplayForwardContext` and `verifyReplayForwardReport` in `app/replay-forward-context.ts`.

## Synthetic first-use journey

A confirmed offline replay with declared SYNTHETIC / CREATED_SYNTHETIC input offers **Export Demo context** and **Continue synthetic Demo**, a plain `/session` link with no public source reference. Export before leaving. Import retains the exact replay, costs, risk, capital and every available page trial; it selects SYNTHETIC_FIXTURE / SYNTHETIC_PLAYBACK but generates no events or Session. A pure offline history requires no account or public-detail reads. Any mixed history still requires fresh checks of every retained public source with a held input; changing the selected origin never erases those dependencies.

Explicit **Prepare synthetic continuation** calls the unchanged deterministic Session example with the exact retained strategy. It repeats an invented price pattern; this is not unseen market data or independent evidence. Every bar, signal, quote and receipt clock shifts by the same whole-timeframe offset so alignment and availability offsets remain intact. The virtual start is strictly after all retained replay/history clocks and the supplied preparation clock. Future virtual timestamps do not establish real delivery. Existing prepared inputs remain fixed; abandon the association to change the setup. Preparation clears input-rights confirmation. Only explicit rights confirmation and **Start Demo session** create a journal; **Next synthetic event** delivers one event at a time. Pause, Emergency, rejected receipts, fees and slippage use the unchanged engine.

**Export synthetic journey report** creates a separate `LOCAL_SYNTHETIC_REPLAY_JOURNEY` with scope `SYNTHETIC_DEMONSTRATION_ONLY`, the unchanged full replay context and the complete reconstructed continuation evidence. It is local only. Public forward-report verification still requires PUBLIC_STRATEGY / SYSTEM_RECEIPT and refuses this wrapper; public Experiment admission still refuses SYNTHETIC_FIXTURE. No public identity, author, independent qualification, live execution or prospective market result is created. The public-source forward path above is unchanged.

Both synthetic preparation and export retain account/lifecycle/source checks, cancellation and stale-result fences. After abandonment, existing exposure remains visible and controllable but an old attempt cannot be relabeled into another association. The context, report and existing continuous-input byte limits still apply, including the existing bounded JSON structure limit; over-limit histories are refused in full rather than trimmed. Trusted local helpers and strict report verification live in `app/synthetic-replay-journey.ts`.

Programmable strategies and locked Search retain their existing separate handoffs. This increment adds no public API, permission, quota, dependency, paid service or live execution.

Local component fixtures exercise actual handlers and trusted simulation/evidence functions with invented inputs and synthetic account/API responses. They do not establish native-browser usability, hosted authentication, genuine market observations, an outside-user trial or product demand.

# Exact research discussions release review

## Resulting behavior

Research gains a direct exact-record link and a bounded incoming-discussion view. Readers can follow immutable counterarguments, forks and revisions without finding them manually in the global board. Existing authorship, sponsorship, falsification, source classifications and write controls remain connected to the selected records.

No agreement, identity count or matching hash qualifies research. Suppressed targets return a tombstone and no discussion content; independently retained children remain subject to their existing lifecycle. No new write command, credential grant, quota, database migration, evaluator, private connection or financial operation is introduced.

An optional expected-author header prevents the UI's frozen command from being published under a different server-authenticated human after an account swap. The server still derives authorship; existing clients without this header keep their prior contract.

## Limits

Pagination is a current bounded read, not a frozen network snapshot or a recursive conversation export. Source authenticity, independent research evaluation, reputation, public repository publication, domain control, hosted authentication and actual browser acceptance remain outstanding. No deployment, permission change, provider run, Live order or investment is performed.

Only complete, consistent responses update the client's accepted visibility projection. A contradictory response makes the requested discussion unavailable without partially installing its claims; other views can still hold their last accepted public records until refreshed. The client cannot erase material already downloaded outside its current views or make a read immune to later moderation.

## Rollback

A maintainer may choose the prior saved version before rollout. This additive read/UI extension can be removed without deleting or reinterpreting retained research publications, moderation history or receipts. Direct incoming relationships remain in their original immutable records, although the prior UI cannot browse them. Production rollout or rollback requires maintainer approval; neither has been performed here.
